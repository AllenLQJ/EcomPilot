# 决策记录

规格有歧义或统筹自行裁决处，供交付报告披露。

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 满减/券/凑单的精确规则 | 固化于 `contracts/module_interfaces.md` 第 2 节 | 路线图只给流程，需无歧义规格才能让实现与暴力对照独立比对 |
| 2 | 真实缺货是否写入 CLOSED_OUT_OF_STOCK 订单 | 不落库，仅返回 422 | 若落库，同一幂等键重试会重放"缺货订单"，与补货后重试语义冲突 |
| 3 | 售后越权订单的返回码 | 统一 404 NOT_FOUND | 防订单号枚举；验收标准允许 403 或 404 |
| 4 | 新增表 `promo_rules`、`aftersale_requests` | 补充到 schema | 路线图实体清单未覆盖满减规则与 C 端售后申请 |
| 5 | 乐观锁重试 | 首次 + 3 次重试，退避 20/50/100ms（加 0~50% 抖动） | 对应"重试 3 次"，抖动减少同步碰撞 |
| 6 | 同一幂等键并发 | 先用 MySQL `GET_LOCK` 串行，再以唯一索引兜底 | 避免重复请求各自扣库存再回滚造成假冲突 |
| 7 | Agent Hub 工作项不得带 acceptance | 创建工作项时省略 acceptance | `no_extra` 会使所有任务瞬时 KeyError 失败 |
| 8 | 报价是否自动用券 | 默认不用；显式 `coupon_ids` 或 `auto_coupon=true` 才用 | 更保守：避免未经用户同意消耗券；验收用例 AC-TX-04 要求热水器实付恰为 112000 |
| 9 | 接入真实 EcomNLU | 先用适配器（`adapters/ecomnlu_adapter.py`，逐句调 `/api/predict`），后因 EcomNLU 仓库新增原生接口 `POST /api/v1/nlu/analyze`（EcomNLU commit d05c81c，契约 v1.3 §3.7）**适配器已删除**，Pilot 直接调用，请求/响应与桩一致。类别→店铺 catalog 品类的映射放在 EcomNLU 的 `configs/base.yaml`（`analyze.categories`）；置信度 <0.65 → ABSTAIN；情感模型未配置时返回 NEUTRAL 而不猜 | Pilot 实际发送 `scene_type=aftersales/shopping`，而桩只认 `AFTER_SALE_FEEDBACK` 才加急；原生接口两种写法都认（`analyze.priority_boost_scenes`）。该模型是评论分类模型，对导购/售后吐槽文本的效果未验证；**真实模型联调待模型目录就位**，目前只用确定性假模型验证过 HTTP 链路（Pilot 的真实客户端代码 ↔ EcomNLU 的真实应用） |
| 10 | 买家补证据入口 | Pilot 新增 `GET /api/v1/aftersales/{claim_no}`（进度）与 `POST …/{claim_no}/evidence`（转发 Ops 的补证据内部接口）；Ops 新增 `GET /internal/v1/claims/{claim_no}/status`（最小状态）。他人/跨租户申请一律 404；Ops 的 409 映射为 `INVALID_ORDER_STATE`；Ops 不可用时进度接口退回本地状态并标 `ops_available=false` | 此前 NEED_MORE_EVIDENCE 后买家没有入口，申请只能卡住。同时修复一个既有缺陷：自定义校验器抛错时 400 响应体含不可序列化的 ctx 导致 500，现只返回 loc/msg/type |
| 11 | 官方 MCP / A2A 协议层 | 新增 `protocols/a2a_gateway.py`（:8090，a2a-sdk 1.3，JSON-RPC，每个代理一个标准 Agent Card，请求转发到代理自带的 `/a2a/invoke`）与 `protocols/mcp_server.py`（mcp SDK 2.3，stdio 与 streamable-http :8091，三个只读工具复用 `pilot.mcp_tools`）。两个 SDK 需要 pydantic ≥2.11 / starlette 1.x，而主栈固定在 pydantic 2.10.4 / starlette 0.41.3（fastapi 0.115.6），所以**协议层放独立虚拟环境 `.venv-proto`**（`requirements-protocols.txt`），主栈不升级。测试：`.venv-proto/bin/python -m pytest -c pytest-protocols.ini`（13 个，含官方客户端、真实 stdio 子进程） | 先试过把 SDK 装进主 venv：starlette/pydantic 被升级后 fastapi 0.115 直接报错，已回滚到固定版本。协议里的 data part 是 protobuf Struct，数字线路上变成 112000.0：入站还原成 int，出站另附原样 JSON 文本 part。Pilot 内部代理互调和进程内工具调用仍是原来的自定义方式，没有改成官方协议；协议层无认证，仅绑定本机 |
