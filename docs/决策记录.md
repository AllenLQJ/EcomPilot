# 决策记录

规格有歧义或统筹自行裁决处，供交付报告披露。

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 满减/券/凑单的精确规则 | 固化于 `contracts/module_interfaces.md` 第 2 节 | 路线图只给流程，需无歧义规格才能让实现与暴力对照独立比对 |
| 2 | 真实缺货是否写入 CLOSED_OUT_OF_STOCK 订单 | 不落库，仅返回 422 | 若落库，同一幂等键重试会重放"缺货订单"，与补货后重试语义冲突 |
| 3 | 售后越权订单的返回码 | 统一 404 NOT_FOUND | 防订单号枚举；验收标准允许 403 或 404 |
| 4 | 新增表 `promo_rules`、`aftersale_requests` | 补充到 schema | 路线图实体清单未覆盖满减规则与 C 端售后申请 |
| 5 | 乐观锁重试 | 首次 + 3 次重试，退避 20/50/100ms（加 0~50% 抖动） | 对应"重试 3 次"，抖动减少同步碰撞 |
| 6 | 同一幂等键并发 | 先用 MySQL `GET_LOCK` 串行，再以唯一索引兜底 | 避免重复请求各自扣库存再回滚造成假冲突 |
| 7 | Agent Hub 工作项不得带 acceptance | 创建工作项时省略 acceptance | `no_extra` 会使所有任务瞬时 KeyError 失败 |
| 8 | 报价是否自动用券 | 默认不用；显式 `coupon_ids` 或 `auto_coupon=true` 才用 | 更保守：避免未经用户同意消耗券；验收用例 AC-TX-04 要求热水器实付恰为 112000 |
